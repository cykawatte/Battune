# ADR 0007 — Explicitly approved adapter mode and local signature pinning

Accepted for local development, 2026-10-11. Physical validation pending.

Native PowerUI exposes only OS-reported limits. The user requested arbitrary
limits, discharge and calibration, and retained approval of low-level access.
The host's unprivileged direct-charge probes return NotPrivileged or missing-key
errors; CHIE adapter metadata is readable. Root/private-entitlement requirements
must not be inferred from those user-process results.

Implement a separate optional fixed-key adapter backend. Require administrator
installation, a bounded off/on/readback test, then user activation. Use software
hysteresis, physical-cable detection, a root ownership journal, lease/watchdog and
sleep restoration. Describe extra battery cycling and lack of sleep enforcement.
No arbitrary writes, automatic fallback, SIP change or claim of physical success.

A local ad-hoc build can be explicitly installed using a root-owned manifest of
exact app/helper code hashes plus bundle identifiers, enforced on both XPC peers.
This is a narrower authorization than a blanket unsigned development bypass.
Rebuilds require matching reinstallation. Apple-signed distributions retain the
existing Team-ID path. The package is prepared without installing it.
